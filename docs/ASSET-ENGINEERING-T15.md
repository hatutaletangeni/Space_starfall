# STARFALL T15 — Asset Manager, Physically Effective Workbench and Test-to-Design Provenance

**Baseline:** verified T14 branch `feature/t14-science-evidence-map` at commit `0d0053d401d383bcd4421fa013ff3849cb654890`. T12/T13/T14 remain separate draft branches; `main` still retains the prior stable T11 release.

## Core contract

The original `StarfallVehicles` definition+state and `StarfallEngineering7A` registry remain the only authoritative owners of actual ship and local science-rover assemblies. All new T15 fields are **diagnostic/provenance only**, stored at `SF.equipmentT15` (schema 15): monotonically numbered bounded service-event history and at most one validated previous installed configuration for each original vehicle identity. No second battery, wheels, inventory, fuel or experiment-result store is introduced. Existing saves without T15 data restore an empty event log and no undo; no fabricated service history.

The original `StarfallResearchUI7E.store` remains the owner of original plans, runs and blueprints. A T15 blueprint application must match *all*: selected named original asset ID, correct type, matching validated saved source run, successful model result, matching blueprint source-run ID, identical definition, intact observation/photo reference lists, not imported, not bench-only, currently stopped and safe. An old or imported blueprint does not silently turn a rover into another vehicle. A blueprint whose definition is unchanged is a no-op and is **refused**, rather than reported as a successful machine upgrade. Original rover bench-only `gearRatio`/`wheelScale` trials and rocket trials stay **bench-only**, because there is no installed runtime control exposing those nonphysical parameters. Source experiments do **not** grant new hardware automatically.

## Actual installed hardware and consequences

- **Rover original battery:** `battery-rover` 18 MJ / 165 kg and `battery-rover-long` 32 MJ / 260 kg. Swapping affects original vehicle actual `batteryCapacityJ`, discharge/charge watts, evaluated mass and storage limits, while preserving the *existing stored Joules* (never adding energy).
- **Original solar panels:** 6.5 m² / max 2.4 kW versus 11 m² / max 4.3 kW. Live `StarfallPower.generation` receives the newly evaluated part stats. Actual energy production still requires real sun incidence and physical charging time.
- **Original motor and wheels:** `rover-motor` 1,300 N·m versus `rover-motor-efficient` 1,200 N·m; `wheels-standard` six wheels/traction 0.70 versus `wheels-grippy` six wheels/traction 0.91. The original `StarfallRoverDynamics.sixWheels` receives the replaced real machine's mass/torque/radius/traction and modifies terrain force, slip and movement. No gearbox, model collider or rover geometry is rewritten.
- **Science suites:** The original `science-suite-rover` remains fully backward compatible (all original eight instruments). Two **optional, compatible new installed modules** add constrained jobs: `science-suite-rover-geo` (spectrometer, thermometer, barometer, magnetometer, radar, seismometer, contact sampler; 62 kg, 360 W nameplate) and `science-suite-rover-bio` (spectrometer, thermometer, barometer, bioassay, contact sampler; 71 kg, 420 W). The local deployed-at-ship rover's real `RT.acquireFieldReading` rejects any sensor not in the current installed module **before** sampling or charging, and still uses unchanged 4A real timing/power/range. Remote T06 rovers retain their original factory science suite: no false remote part installation or teleport service.
- **Ship avionics:** Original `avionics-ship` 900 W / 170 kg retains its original 45-scene-unit, 128 kbit/s, 60 W transmit model. Optional `avionics-ship-long` is 1,450 W / 225 kg and **actually drives T03 radio reach 85 scene units, 192 kbit/s bandwidth and modeled 95 W transmitter**, with the original ship electrical bus paying its higher avionics load. Real T03 LOS, same-body transmitter/receiver, finite packet bytes and source-debited energy remain mandatory. The T13 legacy emergency real battery radio remains backward compatible.
- **Ship engines/tanks, radiators, battery, solar:** Existing component options already update original 7B engineering ship dry/wet mass, thrust, Isp, temperature, inertia, delta-v, `StarfallPower.step` and T13 docking reserve. No rocket/spaceflight integrators or hull geometry are rewritten.
- **Satellite payloads and rocket stages:** Existing T07 `sensor` selection and T07 power/slew/pointing/availability remain the only genuine satellite payload operation. The original Rocket Lab 7B already computes stage masses/thrust/fuel/delta-v; T15 leaves its force integrator intact. Remote satellite replacement by a Workbench design is **not** introduced; it would require a real EVA/service/physical docking contract.

The T00 `technology-contracts.json` source inventory is extended by exactly the **three newly introduced optional components** with explicit source, condition, limitations and unverified labels. Its historical baseline SHA is deliberately not misrepresented as a new baseline.

## Safety, rollback and repair

A Workbench apply requires landed ship (and undocked T13 umbilical) or original local parked rover on the same world (no ongoing auto-drive, truck occupation or active winch), original asset ID unchanged, valid original component types/mount points, component-family constraints and nonidentical part IDs. Before the first mutation T15 calculates the **same original `StarfallVehicles` evaluator** before/after, validates event-cap space and stages an entire vehicle snapshot. Only after the actual owner store matches predicted part IDs and energy exactly is the new definition saved. Failure restores original vehicle store.

Each accepted change logs original part IDs, actual mass, battery capacity, solar rating, torque, traction, ship thrust, actual before/after battery Joules, simulation time, originating Workbench or 7E run/blueprint and original photo/observation IDs. Older service records remain in the save. There is a 500-entry hard write limit rather than truncating old entries.

**RESTORE PREVIOUS INSTALLED PARTS** reapplies the validated previous assembly to the *actual owner store*, appends an audit event, restores saved baseline part IDs and **preserves currently available fuel/Joules**, clamped only if reverting to a smaller capacity. No automatic free recharge, repair, replacement inventory or cargo is fabricated. Restoration must pass the same parked safety checks.

T15 fault descriptions are derived only from original persisted hull health, 390 K overheating threshold, 5% battery warning and real load shedding. An `OUT OF SERVICE` status means a real disabled electrical load, shed bus or disabled/invalid installed component; inactive legacy electric model is labeled `MODELLED`, not as measured voltage. The existing **T12 physical field-repair flow** remains the only rover repair actuator (EVA proximity, real installed component, actual truck battery energy/tool cost and lockout). Asset Manager has a link to that original repair flow, not a parallel free-heal action. Direct spacecraft component repair is **not independently modeled**; change/restore remains a service action with explicit safe operation and not a fictitious hull-healing process.
